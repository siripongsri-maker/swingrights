# SWING RIGHTS, คู่มือส่งมอบระบบ (Handoff Manual)

ระบบรับแจ้งและจัดการเคสการละเมิดสิทธิของมูลนิธิ SWING ที่ https://swingrights.app
เอกสารฉบับนี้เขียนจากโค้ดและฐานข้อมูลจริงของโปรเจกต์ ณ วันที่ 20 ตุลาคม 2026
ผู้อ่านเป้าหมายคือเจ้าหน้าที่ที่ดูแลเคสและดูแลระบบ ไม่จำเป็นต้องเขียนโค้ดเป็น

---

## 1. บัญชีและสิทธิ์การเข้าถึง

### 1.1 บัญชีเจ้าหน้าที่ทั้งหมด (สอบถามจากฐานข้อมูลจริง)

| อีเมล | ชื่อที่แสดง | บทบาท | สถานะ |
|---|---|---|---|
| admin@swing.demo | แอดมินเดโม | admin | active (ใช้งานได้) |

ขณะนี้มีบัญชีเจ้าหน้าที่เพียงบัญชีเดียวคือบัญชี demo นี้

### 1.2 บัญชี demo admin@swing.demo

- ยังใช้งานอยู่ และเป็นบัญชี admin เพียงบัญชีเดียวของระบบ
- ขั้นตอนปิดบัญชีหลังสร้าง admin คนใหม่ (ทำตามลำดับ ห้ามข้าม):
  1. ล็อกอินด้วย admin@swing.demo แล้วไปที่หน้า "ผู้ใช้" (/admin/users)
  2. เชิญเจ้าหน้าที่ใหม่ด้วยอีเมลจริงของอ๋อ กำหนดบทบาท admin
  3. ให้อ๋อเปิดลิงก์ในอีเมล ตั้งรหัสผ่าน แล้วล็อกอินทดสอบว่าเข้า /admin ได้
  4. ล็อกอินกลับด้วย admin@swing.demo อีกครั้ง แล้วกด "ระงับ" บัญชี admin@swing.demo
- ระบบกันไม่ให้ระงับหรือลดสิทธิ์บัญชีตัวเอง จึงต้องมี admin คนใหม่ใช้งานได้จริงก่อนเสมอ

### 1.3 การจัดการบัญชีในหน้า "ผู้ใช้" (/admin/users, เฉพาะ admin)

- **เชิญเจ้าหน้าที่ใหม่**: กรอกอีเมล ชื่อ และบทบาท (admin / manager / caseworker / viewer) ระบบส่งอีเมลเชิญให้ตั้งรหัสผ่าน
- **อนุมัติคำขอสมัคร**: เจ้าหน้าที่ที่สมัครเองผ่านหน้า /admin/signup จะเข้าคิว "รออนุมัติ" admin เลือกบทบาทแล้วกด "อนุมัติ" หรือ "ปฏิเสธ"
- **เปลี่ยนบทบาท**: เลือกบทบาทใหม่จากรายการของผู้ใช้คนนั้น ระบบแทนที่บทบาทเดิมทั้งหมด
- **ระงับ/คืนสิทธิ์**: กดปุ่มระงับ ผู้ใช้จะถูกเด้งออกจากระบบทันทีและล็อกอินไม่ได้ จนกว่าจะกดคืนสิทธิ์
- **รีเซ็ตรหัสผ่าน**: กด "รีเซ็ตรหัสผ่าน" ระบบส่งอีเมลลิงก์ตั้งรหัสใหม่ไปให้ (ผู้ใช้ทำเองก็ได้ที่ปุ่ม "ลืมรหัสผ่าน" ในหน้า /admin/login)

### 1.4 ความปลอดภัยของการล็อกอิน

- **ออกจากระบบอัตโนมัติ**: เจ้าหน้าที่ที่ล็อกอินค้างไว้โดยไม่ใช้งาน 20 นาที ระบบเตือนล่วงหน้า 1 นาที แล้วออกจากระบบอัตโนมัติ เพื่อป้องกันการเปิดจอทิ้งไว้ในสำนักงาน
- **TOTP (ยืนยันตัวตนสองชั้น)**: หน้าล็อกอินรองรับการถามรหัส 6 หลักสำหรับบัญชีที่เปิด TOTP ไว้แล้ว แต่ในหน้าตั้งค่าของระบบยังไม่พบหน้าจอสำหรับเปิดใช้ TOTP ด้วยตนเอง [ต้องยืนยัน] วิธีเปิดใช้และตั้งค่าแอปยืนยันตัวตน

### 1.5 บริการภายนอกที่ระบบเชื่อมอยู่

ค่าลับทั้งหมดเก็บใน Lovable Cloud (Project Settings → Secrets) หรือจัดการผ่าน Connectors ไม่มีการเขียนค่าลับไว้ในโค้ด

| บริการ | ใช้ทำอะไร | ชื่อตัวแปร | สถานะ |
|---|---|---|---|
| Lovable AI Gateway | คำถามติดตาม, ร่างเอกสาร, วิเคราะห์เคส, อ่านเสียง, สังเคราะห์เสียง | LOVABLE_API_KEY | ตั้งค่าแล้ว (ระบบจัดการให้) |
| Google Maps | แผนที่หน่วยงานภาคีและปักหมุดพื้นที่ | GOOGLE_MAPS_API_KEY, GOOGLE_MAPS_BROWSER_KEY, GOOGLE_MAPS_TRACKING_ID | ตั้งค่าแล้ว (ผ่าน Connector) แต่ [ต้องยืนยัน] ว่าคีย์จำกัดโดเมน swingrights.app แล้วหรือยัง |
| Google Search Console | ตรวจ SEO ของเว็บ | GOOGLE_SEARCH_CONSOLE_API_KEY | ตั้งค่าแล้ว (ผ่าน Connector) |
| LINE Messaging API | แจ้งเตือนเคสเสี่ยงสูง/เกิน SLA เข้ากลุ่มเจ้าหน้าที่ | LINE_CHANNEL_ACCESS_TOKEN, LINE_ALERT_TO | ยังไม่ได้ตั้งค่า แจ้งเตือนผ่าน LINE จึงยังไม่ทำงาน |
| Resend (อีเมล) | แจ้งเตือนทางอีเมลสำรอง | RESEND_API_KEY, ALERT_EMAIL_FROM, ALERT_EMAIL_TO | ยังไม่ได้ตั้งค่า |
| ล็อกอินด้วย Google / Apple (ผู้รายงาน) | ปุ่มในหน้า /signin | ตั้งค่าในระบบ auth ของ Lovable Cloud | [ต้องยืนยัน] ว่าเปิด provider ทั้งสองแล้วหรือไม่ ถ้ายัง ปุ่มจะขึ้น "Unsupported provider" |
| ฐานข้อมูลและ auth | Lovable Cloud ในตัว | SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY | ตั้งค่าอัตโนมัติ ไม่ต้องจัดการ |

### 2.2 ความต่างของ /report กับ /intake

- **/intake**: เจ้าหน้าที่ SWING บันทึกให้ผู้รับบริการระหว่างคุยหน้างาน เน้นอัดเสียง ถ่ายรูปหลักฐาน แบบคัดกรอง และลายเซ็น มีขั้นตอน consent, reporter, victim, voice, assess, ai, referral, signature, confirmed

## 3. เส้นทางของเคส ตั้งแต่แจ้งจนปิดเคส

1. ผู้แจ้งเปิด /report (หรือเจ้าหน้าที่บันทึกผ่าน /intake) ตอบคำถาม แนบเสียง/รูป ยินยอม PDPA แล้วส่ง
2. ระบบออกรหัสเคสรูปแบบ SW-XXXXXXXX แสดงหน้าสำเร็จพร้อมปุ่มคัดลอกรหัส รหัสไม่ปรากฏใน URL
3. ผู้แจ้งนำรหัสไปเช็กที่ /track ได้ทุกเมื่อ หรือสมัครบัญชีเพื่อผูกเคสจากเครื่องเดิมเข้ากับบัญชี
4. เคสเข้าคิวเจ้าหน้าที่ที่ /admin เจ้าหน้าที่รับเคส เปลี่ยนสถานะ ถามคำถามกลับ (ผู้แจ้งตอบได้จาก /track) ส่งต่อหน่วยงาน จนปิดเคส
5. สถานะเคสเปลี่ยนโดยเจ้าหน้าที่ที่มีสิทธิ์แก้ไข (admin, manager, caseworker); viewer ดูได้อย่างเดียว การเปลี่ยนเป็นสถานะปิดท้าย (เสร็จสิ้น/ยกเลิก) มีหน้าต่างยืนยันก่อน [ต้องยืนยัน] รายชื่อสถานะทั้งหมดและคำแปลของแต่ละสถานะบนหน้าจอ
6. **ระดับความเสี่ยง แดง/เหลือง/เขียว**: คำนวณจากคำตอบแบบคัดกรอง [ต้องยืนยัน] เกณฑ์แบ่งสีแบบละเอียด แบบคัดกรองมี 2Q/9Q (คัดกรองภาวะซึมเศร้าและความเสี่ยงฆ่าตัวตาย) และ NRM (คัดกรองการค้ามนุษย์) ผลบวกจะยกระดับความเสี่ยงและสร้างการแจ้งเตือนอัตโนมัติ
7. **SLA 24 ชั่วโมง**: เคสใหม่ต้องมีเจ้าหน้าที่ตอบครั้งแรกภายใน 24 ชั่วโมง งานอัตโนมัติ "sla-warning-hourly" ทำงานทุกชั่วโมง (นาทีที่ 0) สแกนเคสที่ใกล้หรือเกิน SLA แล้วสร้างการแจ้งเตือน พร้อมส่งต่อขึ้นหัวหน้า (escalation) อัตโนมัติ แจ้งเตือนผ่าน LINE/อีเมลจะออกเมื่อตั้งค่า secret ตามข้อ 1.5 เท่านั้น แต่การแจ้งเตือนในระบบ (หน้า /admin) ทำงานอยู่แล้ว

## 4. งานประจำวันของเจ้าหน้าที่

### 4.1 จัดการเคส
1. ล็อกอินที่ /admin/login แล้วเปิดแท็บ "คิวเคส" ที่ /admin
2. เปิดเคสจากรายการ (เรียงตามความเร่งด่วน) เข้าหน้ารายละเอียด /admin/case/:id
3. รับเคสเข้า "เคสของฉัน" (/admin/caseload) หรือมอบหมายให้เจ้าหน้าที่คนอื่น
4. ตั้งวันติดตามงาน (follow-up) ระบบบันทึกเมื่อเลือกวันจากปฏิทิน
5. พิมพ์คำถามถามผู้แจ้งกลับ ผู้แจ้งจะเห็นคำถามเมื่อเช็กรหัสที่ /track และตอบกลับได้จากหน้าเดียวกัน

### 4.2 เปิดข้อมูลส่วนบุคคลและหลักฐาน
- ในหน้าเคส กดเปิดเผยข้อมูลส่วนบุคคล (ชื่อ เบอร์ ที่อยู่) ได้เฉพาะผู้มีสิทธิ์ **ทุกครั้งที่เปิด ระบบบันทึกไว้ในบันทึกการเข้าถึงพร้อมชื่อผู้เปิดและเวลา ย้อนลบไม่ได้**
- ไฟล์เสียงและรูปหลักฐานเปิดผ่านลิงก์ชั่วคราว (signed URL) ฟัง/ดูได้จากหน้าเคสโดยตรง

### 4.3 ส่งต่อหน่วยงานภาคี
1. เปิดหน้า /admin/partner-search ค้นหาหน่วยงานตามจังหวัด/บริการ/ระยะทางบนแผนที่
2. จากหน้าเคส เลือกหน่วยงานแล้วสร้างการส่งต่อ ระบบออกลิงก์ลับ (token) ส่งให้หน่วยงาน
3. หน่วยงานเปิดลิงก์ /referral/:token เพื่อกดรับหรือปฏิเสธพร้อมหมายเหตุ โดยไม่ต้องมีบัญชีระบบ

### 4.4 AI ร่างเอกสารและพิมพ์รายงาน
- ในหน้าเคส กดร่างเอกสาร (DocumentDraftDialog) ระบบใช้ AI ร่างตามแบบฟอร์ม เจ้าหน้าที่ตรวจแก้ก่อนพิมพ์เสมอ
- ปุ่มพิมพ์รายงานเคสพิมพ์สรุปเคสเป็นเอกสารกระดาษได้

### 4.5 ทบทวนสิทธิ์รายเดือน

## 5. ข้อมูลส่วนบุคคลและความปลอดภัยของผู้แจ้ง

- ระบบเก็บ: เรื่องเล่า คำตอบแบบคัดกรอง เสียง รูป พื้นที่เกิดเหตุ และ (ถ้ายินยอม) ช่องทางติดต่อ
- ชื่อจริง เบอร์ และข้อมูลตัวตนอื่นแยกเก็บในตาราง case_pii อ่านได้เฉพาะผ่านฟังก์ชันที่ตรวจสิทธิ์ และทุกการเปิดถูกบันทึกใน case_access_log
- การส่งออกข้อมูลทุกครั้งถูกบันทึกใน case_exports
- ระบบเตือนใต้ช่องพิมพ์อิสระไม่ให้กรอกเลขบัตรประชาชน พาสปอร์ต หรือข้อมูลตรวจคนเข้าเมือง (ตรวจด้วยรูปแบบข้อความใน src/lib/piiGuard.tsx)
- ข้อมูลที่ตัดออกก่อนส่งให้ AI: [ต้องยืนยัน] รายละเอียดว่าฟังก์ชัน AI ตัดชื่อ/เลขเอกสารออกก่อนส่งโมเดลระดับใด (โค้ดมีการคัดกรอง PII ฝั่งหน้าเว็บ และการแจ้งเตือนส่งเฉพาะรหัสเคส แต่ยังไม่ได้ยืนยันการตัดข้อมูลทุกจุดฝั่งเซิร์ฟเวอร์)
- **การลบเคสเป็น soft delete**: เคสถูกทำเครื่องหมายลบ (deleted_at) ไม่ถูกลบจริง และฐานข้อมูลปิดสิทธิ์ DELETE แทบทุกตาราง เพื่อให้ตรวจสอบย้อนหลังได้
- การสำรองข้อมูล: ดูแลโดย Lovable Cloud อัตโนมัติ [ต้องยืนยัน] รอบการสำรองและวิธีกู้คืน
- **ข้อควรระวัง**: ในบริบทที่งานบริการและการใช้สารยังผิดกฎหมาย ข้อมูลเคสอาจกระทบความปลอดภัยของผู้แจ้งโดยตรง ห้ามคัดลอก ส่งออก หรือส่งต่อข้อมูลส่วนบุคคลนอกเหนือความจำเป็น ใช้การส่งต่อผ่านลิงก์ token ของระบบเท่านั้น และอย่าแชร์หน้าจอเคสในที่สาธารณะ

## 10. ความเสี่ยงที่ยังเปิดอยู่ (ไม่ได้แก้ในงานส่งมอบนี้)

1. **ฟังก์ชันสาธารณะหลายตัวเรียกได้โดยไม่ต้องล็อกอิน** (analyze-case, track-case, transcribe-audio, notify-case, upload-case-media, referral-respond ตั้ง verify_jwt = false) จำเป็นสำหรับการแจ้งแบบไม่ระบุตัวตน บางตัวมีตัวจำกัดจำนวนครั้ง (rate limit) แต่ [ต้องยืนยัน] ว่าครบทุกฟังก์ชัน ผลกระทบ: ถูกยิงเรียกถี่จนเสียเครดิตได้ ความเร่งด่วน: ปานกลาง
2. **หน้า /intake ไม่ได้อยู่หลังระบบล็อกอิน** ใครมีลิงก์ก็เปิดแบบบันทึกเคสของเจ้าหน้าที่ได้ ผลกระทบ: มีเคสปลอมเข้าระบบได้ ความเร่งด่วน: ปานกลาง
3. **ข้อมูลหน่วยงานภาคี (referral_partners) อ่านได้โดยบุคคลทั่วไป** เพื่อให้หน้าแผนที่สาธารณะทำงาน ผลกระทบ: เบอร์/อีเมล/ที่อยู่หน่วยงานเป็นสาธารณะ ความเร่งด่วน: ต่ำ (เป็นข้อมูลที่ตั้งใจเผยแพร่) แต่ควรตรวจว่าไม่มีข้อมูลภายในปนอยู่
4. **บัคเก็ตรูป case-photos ไม่ได้จำกัดขนาดไฟล์** (case-audio จำกัด 25 MB) ผลกระทบ: พื้นที่จัดเก็บโตเร็วผิดปกติได้ ความเร่งด่วน: ต่ำ
5. **ช่องทางแจ้งเตือน LINE/อีเมลยังไม่ได้ตั้งค่า** เคสเสี่ยงสูงจึงเตือนได้เฉพาะในระบบ ผลกระทบ: เจ้าหน้าที่ที่ไม่ได้เปิดหน้าเว็บอาจไม่ทราบเคสด่วน ความเร่งด่วน: สูง ควรตั้งค่าก่อนใช้งานจริงเต็มรูปแบบ
6. **ยังไม่พบหน้าจอเปิดใช้ TOTP ด้วยตนเอง** ทั้งที่หน้าล็อกอินรองรับแล้ว ความเร่งด่วน: ปานกลาง
