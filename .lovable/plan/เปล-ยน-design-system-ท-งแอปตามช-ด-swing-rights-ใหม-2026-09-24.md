# เปลี่ยน Design System ทั้งแอปตามชุด SWING RIGHTS ใหม่

## เป้าหมาย
ปรับภาพลักษณ์ทุกหน้าตามไฟล์แนบให้เป็นระบบเดียวกัน โดยไม่เปลี่ยนการทำงาน เส้นทาง ข้อมูล สิทธิ์ผู้ใช้ ข้อความหลายภาษา หรือระบบหลังบ้าน

## งานที่จะทำ
1. **ติดตั้งอัตลักษณ์ใหม่**
   - ใช้สีบานเย็น `#CC0099` เป็นสีแบรนด์และปุ่มหลักเพียงจุดเดียวต่อหน้าจอ
   - ใช้ชาร์โคลสำหรับหัวข้อ/ปุ่มรอง พื้นหลังฟ้าอ่อน การ์ดขาว และสีสถานะแยกเขียว–เหลือง–แดง
   - ใช้ Bai Jamjuree สำหรับหัวข้อ, IBM Plex Sans Thai สำหรับเนื้อหา และ IBM Plex Mono สำหรับรหัสเคส/ตัวเลข
   - รองรับโหมดสว่างและมืดตาม token ในชุดแนบ

2. **เปลี่ยนไฟล์แบรนด์และสื่อ**
   - ใช้ logo mark ใหม่ในส่วนหัว และ lockup ใหม่ในหน้าแรก/เอกสารพิมพ์
   - เปลี่ยน favicon, app icon และภาพแชร์ลิงก์ตามไฟล์แนบ
   - ใช้โลโก้ผู้สนับสนุนจากชุดใหม่ เรียง UNAIDS → APCOM → Youth LEAD → SWING เสมอ
   - เก็บภาพขนาดใหญ่ผ่านระบบไฟล์สื่อของแอป และคง favicon เป็นไฟล์จริง

3. **ปรับส่วนประกอบกลางทั้งระบบ**
   - ปุ่มหลักสูง 48px มุม 12px; ปุ่มรอง 40px; ปุ่มอัดเสียงทรงกลมพร้อมจังหวะขณะอัด
   - การ์ดพื้นขาว เส้นขอบบาง มุม 20px เงาเบา
   - ช่องกรอก กล่องข้อความ เมนู แท็บ ป้ายสถานะ หน้าต่าง และ focus ring ให้ตรงชุดใหม่
   - ปรับหัวเว็บ, Quick Exit, หน้าฟอร์มบนมือถือ, แถบผู้สนับสนุน และส่วนของผู้ดูแลให้ใช้กติกาเดียวกัน

4. **ปรับทุกหน้าที่ใช้งานจริง**
   - หน้าแรก: พื้นเรียบ ใช้ lockup ใหม่ ตัดภาพ botanical/gradient และคงโครงสร้างเนื้อหาเดิม
   - หน้าแจ้งเรื่อง/สัมภาษณ์: กล่องสนทนาและเครื่องอัดเสียงตามแบบใหม่ โดยไม่เปลี่ยนลำดับคำถามหรือ AI
   - หน้าติดตามเคส, สิทธิ, ความเป็นส่วนตัว, กู้คืน, ส่งต่อหน่วยงาน และรายงานโครงการ
   - หน้าเข้าสู่ระบบและหน้าผู้ดูแลทั้งหมด รวมตาราง KPI, SLA, รายละเอียดเคส, ผู้ใช้, หน่วยงาน และตรวจสิทธิ์
   - เอกสารพิมพ์ใช้โลโก้และสีใหม่ โดยไม่เปลี่ยนเนื้อหาหรือข้อมูลในเอกสาร

5. **ตรวจความครบถ้วน**
   - ตรวจสีที่เขียนตรงในหน้า/ส่วนประกอบและแทนด้วย token ที่เหมาะสม
   - ตรวจหน้าจอมือถือและเดสก์ท็อป รวมโหมดมืด การอ่านภาษาไทย และการไม่ทับกัน
   - ทดสอบเส้นทางหลัก: หน้าแรก → แจ้งเรื่อง, ติดตามเคส, เข้าสู่ระบบผู้ดูแล → แดชบอร์ด/รายละเอียดเคส
   - ตรวจว่า build ผ่าน และไม่มีข้อผิดพลาดหน้าเว็บ

## รายละเอียดทางเทคนิค
- เปลี่ยนเฉพาะ presentation layer: CSS tokens, Tailwind theme, shared UI variants, branded assets และ class ของหน้าจอ
- ไม่แก้ database schema, RLS, edge functions, API payload, routes, i18n keys หรือ business workflows
- ยึดไฟล์ `design-tokens.json`, CSS token และคำสั่งในชุดแนบเป็นแหล่งอ้างอิงหลัก
